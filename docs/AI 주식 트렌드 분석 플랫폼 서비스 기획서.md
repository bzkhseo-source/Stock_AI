# 왜올랐지 — AI 주식 트렌드 분석 플랫폼 서비스 기획서

Nov 10, 2026 · @서경환

Python 기반 반응형 웹 + PWA로 국내 시장 MVP부터 만들고, 베타 기간에는 프로 기능까지 전부 무료로 열어 사용성을 검증한다.

## 1. 서비스 개요

국내외 시장 데이터·공시·뉴스를 수집해 테마를 탐지하고, 키워드로 관련 종목을 찾아 순위·위험·전망을 보여주는 투자 참고 정보 서비스다. 매수·매도 추천이 아니라 \*\*"왜 움직였는지, 진짜 관련 있는지, 무엇이 위험한지"\*\*를 데이터로 보여주는 것이 목표다.

### 차별점

| 차별점 | 기존 서비스와 다른 점 |
| --- | --- |
| 테마 노출도 % | "관련주" 꼬리표 대신 사업보고서 부문별 매출에서 해당 테마 매출 비중을 수치로 제시 |
| "왜 올랐지?" 원인 추적 | 급등락 시점의 공시·뉴스·해외 연관 종목을 맞춰 원인 후보를 제시, 없으면 "원인 불명" 경고 |
| 글로벌↔국내 공급망 연결 | 해외 이벤트(예: 미국 기업 실적)가 영향을 줄 국내 공급사를 연결해 장 시작 전 브리핑 |
| 위험 우선 표시 | 오버행, 보호예수 해제, 관리종목 위험 등 리스크 배지를 모든 등급에 제공 |
| 점수 성적표 공개 | AI 종합점수의 과거 성과를 백테스트로 공개해 점수 신뢰도를 검증 |

### 운영 원칙

- 정확성 > 객관성 > 최신성 > 논리성. 데이터가 없으면 추정하지 않고 "데이터 없음"으로 표시한다.
- 모든 수치·순위에 출처, 기준 시점, 정렬 기준을 함께 표시한다.
- 확인된 사실과 AI 해석을 화면에서 시각적으로 구분한다 (예: 사실 = 기본 텍스트, 해석 = "AI 해석" 라벨 박스).
- 과거 수익률을 미래 수익률로 표현하지 않고, 기회와 위험을 항상 함께 보여준다.

## 2. 사용자와 등급 정책

초보·중급 투자자(무료)와 활발한 트레이더(프로)를 함께 겨냥하되, **베타 기간에는 모든 사용자에게 프로 기능을 무료로 연다.** 등급 구조는 처음부터 코드에 넣어 두고, 베타 종료 시 설정값만 바꿔 전환한다.

| 구분 | 무료 (정식) | 프로 (정식) | 베타 기간 |
| --- | --- | --- | --- |
| 대상 | 테마를 이해하고 싶은 초보·중급 | 매일 테마를 쫓는 트레이더 | 전체 가입자 |
| 핵심 가치 | 이해하고 안심하기 | 더 빠르고 깊게, 내 종목 중심 | 전 기능 체험 + 피드백 |
| 시세 | 지연 시세 | 지연 시세 (실시간은 추후 검토) | 지연 시세 |
| AI 분석 호출 | 일일 횟수 제한 | 확대 또는 무제한 | 원가 보호용 일일 상한만 적용 |
| 리스크 경고 | 전체 제공 | 전체 제공 | 전체 제공 |
| 점수 성적표 | 전체 공개 | 전체 공개 | 전체 공개 |

### 베타 운영 방식

- 사용자 등급 값은 `free` / `pro` / `beta` 세 가지로 두고, 베타 사용자는 프로 기능 권한을 모두 가진다.
- 프로 기능에는 화면에 "PRO" 배지를 표시해, 사용자가 어떤 기능이 정식 출시 후 유료가 될지 미리 알 수 있게 한다.
- 프로 기능별 사용 빈도를 수집해 정식 등급 배분의 근거로 쓴다 (10장).
- 베타 종료 최소 2주 전에 정식 등급 정책을 공지한다.

## 4. 화면 구성

모바일 하단 탭 5개(PC는 좌측 메뉴)로 구성하고, 모든 화면 상단에 데이터 기준 시점과 "투자 참고 정보" 고지를 고정한다.

| 메뉴 | 화면 | 주요 구성 요소 | 관련 기능 |
| --- | --- | --- | --- |
| 홈 | 시장 대시보드 | 지수 카드, 테마 상승·하락 TOP 10, 거래량 급증, 관심 키워드, 아침 브리핑 카드 | F01, F12 |
| 검색 | 키워드 결과 | 확장 키워드 칩, 관련 산업, 국내·해외 관련주 탭, 연관성 단계 필터, 정렬 드롭다운 | F02, F03, F10 |
| 검색 | 종목 비교표 | 종목명 · 현재가 · 등락률 · 시가총액 · 거래량 · 노출도 % · 종합점수 · 리스크 배지 | F03, F04, F06, F09 |

| 관심 | 관심종목·알림 | 관심 목록, 포트폴리오 노출도, 알림 설정, 이벤트 캘린더 | F14, F15, F19 |
| 공통 | 설정·피드백 | 등급 표시, 점수 성적표, 피드백·설문, 면책 고지 | F18, F21 |

### 화면 규칙

- 모든 순위표 머리에 "정렬 기준 · 기준 시점 · 데이터 출처"를 한 줄로 표시한다.
- 통화와 단위를 수치 옆에 명시한다 (예: 시가총액 `조원`, `USD bn`).
- 우선주·ETF·스팩은 라벨로 구분하고, 거래정지·상장폐지 예정 종목은 회색 처리 + 배지를 단다.
- 단기 급등 종목에는 추격매수 위험 안내를, 저유동성 종목에는 유동성 위험 배지를 붙인다.

## 5. 시스템 아키텍처

사용자가 요청할 때마다 계산하지 않고, 배치가 장 마감 후와 정해진 주기에 지표·점수·브리핑을 미리 만들어 둔다. LLM 비용이 고정되고 화면이 빨라지며, 모든 결과에 기준 시점이 자연스럽게 붙는다.

LLM은 분석 계층에서 문서 해석에만 호출되고, 웹 서버는 LLM을 직접 부르지 않는다.

## 6. 기술 스택

백엔드와 화면 렌더링을 모두 Python으로 처리하는 **FastAPI + Jinja2 + HTMX** 구성을 권장한다. 별도 프론트엔드 빌드 없이 반응형 웹과 PWA(매니페스트 + 서비스 워커)를 만들 수 있다. 무료 티어의 조건은 자주 바뀌므로 개발 착수 시점에 다시 확인한다.

| 영역 | 선택 | 무료 운영 방식 | 비고 |
| --- | --- | --- | --- |
| 웹 서버 | FastAPI + Uvicorn | 오픈소스 | API와 화면을 한 서버에서 제공 |
| 화면 | Jinja2 템플릿 + HTMX + Tailwind CSS | 오픈소스 | JS 최소화, 부분 갱신은 HTMX |
| 차트 | Plotly (Python에서 생성) 또는 Lightweight Charts | 오픈소스 | 주가 캔들 차트는 경량 JS 차트 라이브러리 고려 |
| PWA | manifest.json + service worker | 무료 | 오프라인 캐시, 홈 화면 추가, 웹 푸시 |
| 데이터 처리 | pandas, numpy | 오픈소스 | 수익률·변동성·MDD 계산 |
| 스케줄러 | APScheduler | 오픈소스 | 장 마감 후 배치, 공시 주기 수집 |
| DB | SQLite(개발) → Neon PostgreSQL(운영) | 로컬 무료 / 관리형 무료 티어 | ORM: SQLAlchemy |
| 캐시 | 사전 계산 테이블 (초기) → Redis (필요 시) | 무료 | 순위·점수·브리핑은 배치로 미리 저장 |
| LLM | Gemini API (무료 티어) | 무료 티어 + 일일 상한 | 공급사를 바꿀 수 있게 호출 계층을 분리 |
| 인증 | 이메일 매직링크 또는 소셜 로그인 | 무료 | 베타 사용자 식별·사용량 집계용 |
| 배포 | 무료 PaaS(웹) + 배치는 GitHub Actions 예약 실행 | 무료 티어 | 무료 PaaS는 유휴 시 정지될 수 있어 스케줄러는 별도 실행 고려 |

### 더 빠른 대안

화면 기획을 먼저 검증하고 싶다면 **Streamlit**으로 1\~2주 안에 내부 프로토타입을 만들 수 있다. 다만 PWA·푸시 알림·세밀한 반응형 레이아웃에 제약이 있어, 베타 공개 버전은 FastAPI 구성으로 가는 것을 권장한다. 분석 모듈(`analysis/`)을 화면과 분리해 두면 두 방식 모두에서 그대로 재사용할 수 있다.

## 7. 데이터 소스와 신뢰성 관리

공시·재무는 공식 API(DART)를 쓰고, 시세는 베타 기간에 무료 소스를 쓰되 **공개 정식 출시 전에는 재배포가 허용된 소스로 교체**한다. 비공식 라이브러리는 데이터를 웹에서 가져오는 방식이라 상업적 재배포 조건이 불분명하기 때문이다.

| 데이터 | 1순위 소스 | 대체·보조 | 갱신 주기 | 재배포 확인 |
| --- | --- | --- | --- | --- |
| 공시 목록·원문 | DART Open API (OpenDartReader / dart-fss) | — | 10\~30분 | 공식 API, 이용약관 확인 |
| 재무제표·사업보고서 | DART Open API | — | 분기 | 공식 API, 이용약관 확인 |
| 국내 일별 시세·거래량 | pykrx, FinanceDataReader (베타) | 증권사 Open API (정식 출시 전 교체 후보) | 장 마감 후 1회 + 장중 지연 | 필수 확인 |
| 해외 시세·지수 | yfinance (베타) | 공식 데이터 API (정식 출시 전 교체 후보) | 장 마감 후 1회 | 필수 확인 |
| 수급(기관·외국인) | 증권사 Open API | pykrx | 일 1회 | 필수 확인 |
| 뉴스 | Google 뉴스 RSS 검색 피드 (키 불필요) | — | 30분\~1시간 | 제목·요약·링크만 제공, 원문 저장·재게시 금지 |
| 거시 일정 | 중앙은행·통계기관 공식 일정 | — | 주 1회 | 공식 공개 정보 |

### 품질 규칙

- 종목명과 종목코드를 교차 검증하고, 불일치하면 해당 종목을 표시하지 않고 로그에 남긴다.
- 휴장일과 국가별 시차를 반영해 "기준 시점"을 계산한다 (예: 미국 데이터는 한국 시간 기준 날짜와 현지 날짜를 함께 표시).
- 수집에 실패하면 마지막 성공값과 그 시점을 표시하고, 값을 추정하지 않는다.
- 뉴스는 최초 게시일과 수정일을 따로 저장하고, 같은 사건의 중복 기사는 하나의 이슈로 묶는다.

## 9. 분석 로직

계산 가능한 지표는 코드로 계산하고, LLM은 문서 해석(매출 비중 추출, 원인 매칭 설명, 뉴스 요약)에만 쓴다. LLM이 수치를 만들어내지 않게 하는 것이 핵심이다.

### 9.1 변동성 지표

일간 수익률 r = 오늘 종가 / 전일 종가 − 1 (수정주가 기준)

```latex
\sigma_{annual} = \sigma_{daily} \times \sqrt{252}
```

- 기간 수익률: 1일, 5일, 1개월(21거래일), 3개월(63), 6개월(126), 1년(252)
- MDD: 기간 내 직전 최고가 대비 최대 하락률
- 거래량 급증: 당일 거래량 ÷ 최근 20거래일 평균 거래량 ≥ 3배 (기준값은 베타에서 조정)
- 해외 시장은 국가별 거래일 수를 따로 적용한다.

### 9.2 AI 종합점수 (트렌드 적합도, 100점)

| 항목 | 배점 | 산출 방법 (초안) |
| --- | --- | --- |
| 주가 모멘텀 | 20 | 1개월·3개월 수익률의 테마 내 백분위 |
| 거래량·거래대금 | 15 | 20일 평균 대비 증가율의 테마 내 백분위 |
| 산업 성장성 | 20 | 테마 단위 점수 (테마 거래대금 추세, 관련 공시·뉴스 빈도) |
| 뉴스·이벤트 모멘텀 | 15 | 최근 7일 관련 뉴스·공시 건수와 감성 |
| 사업 연관성 | 15 | 연관성 단계 + 테마 노출도 % |
| 재무 건전성 | 15 | 부채비율, 영업이익 흑자 여부, 이자보상배율 |

- 결과 구간: 80\~100 높음 · 65\~79 양호 · 50\~64 관찰 필요 · 50 미만 낮음
- 누락 항목은 만점 처리하지 않는다. 평가 가능한 항목만으로 100점 환산하고 \*\*데이터 충족률(%)\*\*을 함께 표시하며, 충족률 60% 미만이면 "평가 불가"로 표시한다.
- 점수 화면에 "수익률·상승 확률이 아닌 트렌드 적합도"라는 설명을 고정한다.

### 9.3 테마 노출도 %

1. DART에서 최신 사업보고서의 "사업의 내용"과 부문별 매출 표를 가져온다.
2. LLM이 테마 키워드와 관련된 사업부문과 매출액을 추출하고, **근거 문장을 원문 그대로 함께 반환**한다.
3. 코드가 해당 부문 매출 ÷ 총매출을 계산하고, 근거 문장이 원문에 실제로 있는지 문자열 대조로 검증한다.
4. 검증 실패나 부문 구분이 없는 경우 "노출도 산출 불가"로 표시한다 (추정 금지).
5. 결과는 분기마다 다시 계산하고, 사용자가 "근거 보기"로 원문 링크를 열 수 있게 한다.

### 9.4 "왜 올랐지?" 원인 추적

1. 대상: 당일 등락률 ±10% 이상 또는 거래량 급증 종목.
2. 같은 날과 직전 거래일의 해당 종목 공시, 종목명이 포함된 뉴스, 같은 테마 종목의 동반 움직임, 연결된 해외 종목의 전일 등락을 모은다.
3. LLM은 모은 자료 안에서만 원인 후보를 고르고 출처를 붙인다. 자료 밖의 설명은 쓰지 않는다.
4. 후보가 없으면 "원인 불명 급등/급락 — 주의"로 표시한다.

### 9.5 트렌드 분류 (테마 단위)

급부상 · 상승 지속 · 초기 형성 · 과열 주의 · 하락 전환을 테마 거래대금 증가율, 테마 평균 수익률, 뉴스 빈도 증가율의 조합 규칙으로 판정한다. 기준값은 베타 데이터로 조정하고 화면에 판정 기준을 공개한다.

## 10. 베타 사용성 평가 계획

베타의 목적은 세 가지 질문에 답하는 것이다. ① 차별 기능(노출도, 원인 추적, 리스크 배지)이 실제로 쓰이는가 ② 어떤 프로 기능이 돈을 낼 만한가 ③ 화면이 이해하기 쉬운가.

| 측정 항목 | 방법 | 판단 기준 (초안) |
| --- | --- | --- |
| 기능별 사용 빈도 | `usage_events` 자동 수집 | 프로 기능 중 주간 사용자 비율 상위 3개를 유료 핵심 기능 후보로 |
| 재방문율 | 가입 후 7일·30일 재방문 | D7 재방문율 추세로 아침 브리핑·알림 효과 확인 |
| 첫 검색까지 시간 | 가입 → 첫 키워드 검색 소요 시간 | 길면 온보딩 개선 |
| 과업 성공률 | 5\~8명 대상 과업 테스트 (예: "AI 데이터센터 관련주 중 노출도 가장 높은 종목 찾기") | 과업별 성공률·소요 시간 기록 |
| 사용성 점수 | SUS 설문 10문항 | 점수 추세로 개선 전후 비교 |
| 신뢰도 인식 | "이 정보의 근거를 믿을 수 있다" 5점 척도 | 근거 표시 방식 개선에 활용 |
| 지불 의향 | 프로 기능별 "유료라면 쓰겠다" + 적정 월 요금 질문 | 정식 가격 정책 근거 |
| 정성 피드백 | 화면별 피드백 버튼, 인터뷰 | 주간 단위로 분류·반영 |

### 운영 절차

1. 비공개 베타: 지인·동료 20\~50명, 초대 코드 방식
2. 1주 단위 개선 주기: 피드백 정리 → 수정 → 공지
3. 외부 공개 베타는 하지 않고, 정식 출시 전에 데이터 소스 교체와 법률 검토(12장)를 마친다
4. 베타 종료 보고서: 기능별 사용 데이터 + 설문 결과로 정식 등급 배분 확정

개인정보는 이메일과 사용 기록만 수집하고, 수집 항목과 목적을 가입 화면에 고지한다.

## 12. 규제·법적 리스크 대응

법률 검토는 정식 출시(유료화) 전에 받는다. 그 전까지는 지인 대상 비공개 베타로만 운영하고 초대 코드로 접근을 제한한다. 아래 대응은 기획 단계의 방향이며 법률 자문을 대신하지 않는다.

| 리스크 | 내용 | 대응 방향 |
| --- | --- | --- |
| 유사투자자문업 해당 여부 | 불특정 다수에게 종목 점수·순위를 제공하면 자본시장법상 신고 대상인지 검토 필요 | 공개 베타 전 법률 검토, 필요 시 신고. 매수·매도 표현, 목표주가, 1:1 맞춤 추천 배제 |
| 맞춤 추천으로 보일 위험 | 포트폴리오 노출도·알림이 개인 자문처럼 보일 수 있음 | "정보 제공" 문구 사용, 행동 권유 문구 금지 (예: "매수 타이밍" 금지) |
| 시세 재배포 | 거래소·데이터 제공사 약관상 재배포 제한 | 베타는 비공개 운영, 공개 전 재배포 허용 소스로 교체 |
| 뉴스 저작권 | 기사 원문 저장·게재 시 침해 소지 | 제목·짧은 자체 요약·원문 링크만 제공 |
| AI 오류 | 잘못된 매출 비중, 원인 설명 | 근거 문장 원문 대조, 자료 밖 설명 금지, 화면에 "AI 해석" 라벨 |
| 개인정보 | 이메일, 관심종목, 사용 기록 | 최소 수집, 수집 목적 고지, 탈퇴 시 삭제 |
| 투자 손실 책임 | 이용자 손실에 대한 분쟁 | 모든 화면에 면책 고지, 이용약관에 "투자 판단의 책임은 이용자" 명시 |

### 화면 고지 문구 (초안)

> 본 서비스는 공개 데이터를 바탕으로 한 투자 참고 정보이며 특정 종목의 매수·매도를 권유하지 않습니다. AI 분석은 오류가 있을 수 있고 투자 수익을 보장하지 않습니다. 투자 판단과 그 결과의 책임은 이용자에게 있습니다.
